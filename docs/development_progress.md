## [2026-10-22] 画像描画不具合（キャンバスが真っ暗のまま表示されない問題）の調査と修正

### 1. 発生事象
`python main.py /Users/watanabehiroki/Pictures/TWICE/twice_wl_selfie06.png` を実行してGUIウィンドウが立ち上がるものの、中央のキャンバス領域に画像が描画されず、背景（#161617）のまま表示されない。

### 2. 原因調査（根本原因の特定）
調査の結果、以下の3つの複合的な問題が判明：

1. **起動時の描画ライフサイクルとキャンバスサイズ未確定によるスキップ**:
   - `AvatarEditorApp.__init__` 内で `self.load_image()` を呼び出すが、この時点では Tkinter ウィンドウがまだスクリーンにマッピング（描画完了）されていないため、`self.canvas.winfo_width()` および `winfo_height()` が `1` を返す。
   - `update_canvas()` の冒頭にあるガード条件 `if cw <= 1 or ch <= 1: return` に引っかかり、起動時の画像描画処理が即座にスキップされて終了する。
   - ウィンドウ描画後に発火する `<Configure>` イベント（`on_canvas_resize`）には `if not hasattr(self, "_canvas_initialized"):` という初回限定フラグがあるが、初期の微細なサイズ変更（1x1など）で消費されてしまい、その後の正常サイズ（693x815等）でのリサイズイベントで `update_canvas()` や `reset_zoom()` が呼ばれなくなっていた。

2. **Tkinter Canvas の PhotoImage 参照保持（ガベージコレクション）不備**:
   - `self.photo_img = ImageTk.PhotoImage(bg)` をインスタンス変数に代入しているが、Tkinter の Canvas ウィジェット内部での参照（`self.canvas.image = self.photo_img`）を保持していないため、macOS 環境や Tcl/Tk の内部イベントによって画像リソースが GC / 解放され、表示が消える。

3. **リサイズ追従処理の欠落**:
   - ウィンドウを最大化したりドラッグでサイズ変更しても、キャンバスが再描画されない。

### 3. 設計方針と修正計画
1. **初期描画の確実化**:
   - `__init__` の末尾で `self.after(150, self.reset_zoom)` および `self.after(300, self.update_canvas)` を呼び出し、ウィンドウのマッピングとサイズ確定後に確実に描画を行う。
   - `update_canvas()` 内でサイズが未確定（`cw <= 1 or ch <= 1`）だった場合、無言で終了するのではなく `self.after(50, self.update_canvas)` で自動リトライするフォールバックを組み込む。
2. **リサイズイベント（`on_canvas_resize`）の改善**:
   - `event.width > 1 and event.height > 1` を確認し、未初期化時は `reset_zoom()`、初期化後はウィンドウリサイズに合わせて `update_canvas()` を呼ぶように修正する。
3. **画像オブジェクトの二重参照保持**:
   - `self.canvas.image = self.photo_img` を追加し、GCによる画像消失を防止する。
